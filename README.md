# מערכת ניהול דרישות

אפליקציית Flask לניהול דרישות, תתי-דרישות, שיוך למודולים וזיהוי מי הציע כל דרישה.
ניהול המשתמשים בידי האדמין בלבד.

## מה האפליקציה יודעת לעשות

- **התחברות מאובטחת** — רק משתמשים רשומים נכנסים (סיסמאות מוצפנות).
- **ניהול משתמשים (אדמין בלבד)** — רק את יכולה לרשום, למחוק ולאפס סיסמאות.
- **דרישות** — הוספה, עריכה ומחיקה, עם סטטוס ועדיפות.
- **תתי-דרישות** — לכל דרישה אפשר להוסיף תתי-דרישות (בהיררכיה).
- **מודולים** — שיוך כל דרישה למודול, עם צבע תווית.
- **מי הציע** — לכל דרישה אפשר לבחור מי מהמשתמשים הציע אותה.
- **סינון** — לפי מודול ולפי סטטוס.

## פריסה ב-Railway

1. ב-Railway: **New Project → Deploy from GitHub repo** ובחרי את הריפו.
2. Railway יזהה אוטומטית את `Procfile` ואת `requirements.txt` ויבנה את האפליקציה.
3. **הוספת בסיס נתונים קבוע (חשוב!):** בפרויקט → **New → Database → PostgreSQL**.
   Railway יזריק אוטומטית את המשתנה `DATABASE_URL`, והאפליקציה תשתמש בו לבד.
   *(בלי Postgres הנתונים נמחקים בכל פריסה מחדש — מכיוון שמערכת הקבצים של Railway זמנית.)*
4. **משתני סביבה** (Variables) — מומלץ להגדיר:
   | משתנה | ערך |
   |---|---|
   | `SECRET_KEY` | מחרוזת אקראית ארוכה |
   | `ADMIN_USERNAME` | שם המשתמש שלך לכניסה |
   | `ADMIN_PASSWORD` | סיסמה חזקה |
   | `ADMIN_NAME` | השם שיוצג (למשל: דיקלה) |
5. **דומיין:** בלשונית **Settings → Networking → Generate Domain**.
   תקבלי כתובת בסגנון `https://<שם>.up.railway.app`. אפשר גם לחבר דומיין משלך תחת Custom Domain.

### עדכונים שוטפים
כל `git push` לענף `main` מפעיל פריסה מחדש אוטומטית — בדיוק כמו ב-logistics.

## הערה על האדמין הראשוני
בפעם הראשונה שהאפליקציה עולה ובסיס הנתונים ריק, נוצר אוטומטית משתמש אדמין
לפי `ADMIN_USERNAME` / `ADMIN_PASSWORD`. משם והלאה את מנהלת את כל שאר המשתמשים מתוך המערכת.
